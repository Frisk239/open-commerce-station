## 1. 这是什么产品

开源、只交源码的独立站地基。老板找人部署后，进后台填店、上架、收款，不写代码就能卖实物。

两种口味，一次部署只能选一个：

| 口味 | 顾客 | 收款（原型里用假按钮） |
| --- | --- | --- |
| 国内站 | 中文、人民币 | 支付宝可用；微信灰色「稍后开放」 |
| 出海站 | 默英文美元，可再开语言和货币 | PayPal、Stripe |

不是：托管 SaaS、交钥匙代运营、小程序商城、多商户、主题市场、发卡网。

术语以仓库根目录 `CONTEXT.md` 为准。对话里少用顾客看不懂的词。

## 2. 已经拍死、原型必须遵守

完整条文在 `docs/adr/` 与 `docs/design/`。这里是执行摘要。

**店**

- 一套默认空白店。老板改字、图、商品，不换皮肤、不自由拖拽搭页。
- 店名、标志、小图标、页脚一行字：设置里填一次，页眉、结账、邮件预览一起变。没标志就显示店名。见 `docs/design/store-identity.md`。
- 国内页脚：ICP、公安备案号选填，有号必须能点到工信部/公安查询；空着不显示。出海站没有这些栏。
- 四篇说明永远在：隐私、服务条款、退货、运费。结账和页脚都挂。空页文案：「店主尚未填写」。不卡付款。见 `docs/design/checkout-policy-pages.md`。

**货**

- 实物，要邮寄。数字商品不做。
- 商品 = 名字介绍图；选项名老板自己起（颜色/尺码/容量都行）；能买走的每一款自己的价格和库存。没有选项也算一款。
- 库存 0 不能加入购物车、不能付。
- 分类空着老板建。进店永远有「全部商品」。
- 现价 + 可选划线原价；优惠码老板配，结账输一个码，减在现价上。不要拼团砍价。

**买**

- 看货不用登录。结账必须邮箱+密码。不要游客付、不要短信、不要 Google 按钮（可留「以后」注释，不要画成能点）。
- 标价即实付，结账不加税行。
- 运费：老板配规则（地区/重量/满额包邮）。结账必须选到运费。发货：后台填运单号。
- 国内假支付：支付宝成功。微信按钮在，灰色不可点。出海假支付：PayPal 或 Stripe 成功。

**售后与客服**

- 顾客申请退：未发货同意后直接退；已到货同意后退货再退款。钱不会一点申请就走。不要淘宝仅退款。
- 站内聊天窗，不跳微信/WhatsApp。
- 同一窗：AI 先答（只用说明页 + 登录后的这一单），退钱必须转人工。AI 不能点同意退款。
- 后台有收件箱。订单上下文第一版可展示订单卡，退款按钮可先转到「订单详情里由老板点同意」。

**信与账号**

- 三封信用预览页即可：下单成功、已发货（带单号）、老板来单。设置里有 SMTP 表单，不必真发。
- 后台只有一个老板号。不要店员权限矩阵。

**语言货币**

- 软件按钮带中文、英文。店主语言一份，其它语言没填则回退主语言。
- 语言和货币分开切。记账货币一种，其它货币手填汇率。国内默认中文+人民币，出海默认英文+美元。见 `docs/design/language-and-currency.md`。

**明确不要做进原型**

评价、发票、税引擎、短信、MinIO、对象存储、主题市场、店员、真微信收款、营销中心、博客、搜索可以做成顶栏一个输入框但不必做结果页算法、分销拼团砍价直播、多店切换器。

## 3. 别人的独立站 UI 怎么做（调研结论）

独立站赢在「像一家品牌的官网在卖自己的东西」，不是货架城。

**店面（顾客）**

- Shopify 现在新店默认更接近 Horizon：大图、少框、区块少而清楚；老默认 Dawn 也是「图说话、界面让路」。付费精品主题（Prestige / Impact）更强调全幅摄影、商品卡几乎无边框、结账极静。
- Aesop、Allbirds、Everlane 一类 DTC：商品页几乎是杂志，选项是色块/文字不是下拉超市，价格克制，运费与退货入口诚实出现。结账一步、少打断。
- 国内独立站（InnoShop / BeikeShop 演示）常见问题：后台能力够，店面容易像后台表格或促销条堆满。原型不要学弹窗券、倒计时、漂浮挂件（聊天窗除外）。
- 吸引人进来的是：**一致的照片气质、大图、少字、快的路径（首页 → 商品 → 车 → 结账）**，不是更多按钮。

**后台（老板）**

- Shopify 后台：左栏短、今日待办清楚、订单是主角。Polaris 是后台语言：充足留白、表格可读、没有着陆页英雄区。
- 原型后台要对齐「十分钟上完一件货」，不是数据驾驶舱。

**给本原型的设计读（开工必须写进 HANDOFF）**

- 店面：品牌独立站，给愿意在官网买实物的人，摄影主导、冷静、高信任，不要 SaaS 紫、不要三列同等功能卡、不要微商城红黄爆款条。色板不要默认的米黄+铜色（那是 AI 工艺品站套装）。建议冷灰底 + 一个低饱和强调色（例如深松绿或钴蓝），中英都说得通。
- 后台：经营工具，浅色、密一点、左导航，对齐 Linear / Shopify 后台的安静，不搞玻璃拟态英雄区。
- 空白店：没货时仍然像一家还没上架的品牌站（大留白 + 一句人话），不要「暂无数据」表格空态。

店面可参考技能 `design-taste-frontend` 的反模板条款（禁止 Inter 当默认、禁止三等分功能卡、禁止装饰性滚动提示、强调色只有一个）。后台不要拿那套着陆页规则硬套表格页。

## 4. 技术（只约束原型）

在 `chanpin/` 新建例如 `chanpin/web/`：

- Next.js（App Router）+ TypeScript + Tailwind + pnpm
- 假数据：`chanpin/web/src/mock/` 一份 JSON 或 ts 模块，刷新不丢可用内存 store（zustand 或 React context）
- 路由能分享。不要要用户装 Docker、Postgres、Redis 才能点原型
- 图标：Phosphor 或 Tabler，全家只用一种。不要 Lucide，除非你只能装到它
- 字体：`next/font` 自托管，不要默认 Inter
- 图：可用生成图或 `picsum.photos/seed/...`；禁止用 div 画假商品图
- 中英切换要能演示软件按钮语言；商品译文用 mock 里的字段

启动：`cd chanpin/web && pnpm install && pnpm dev`，默认 `http://localhost:3000`

## 5. 信息架构与路由

原型里用路径区分口味，避免两个仓库：

| 路径 | 谁 |
| --- | --- |
| `/` | 选国内站或出海站（漂亮、短，不是系统安装向导） |
| `/cn/...` | 国内店面 |
| `/global/...` | 出海店面 |
| `/cn/portal/...` | 国内后台（需老板登录） |
| `/global/portal/...` | 出海后台 |

**店面**

- `/` 下的首页、全部商品、分类、商品详情、购物车、登录注册、结账、支付结果、订单详情（登录后）、说明页四篇、申请退货
- 右下角聊天窗（全店面，结账页可缩小但不删除）

**后台（左栏）**

- 首页（待发货、待处理退货、未读聊天）
- 订单
- 商品（含选项与库存）
- 分类
- 优惠码
- 收件箱
- 页面（四篇说明）
- 设置：店铺资料、收款、运费、语言和货币、SMTP、客服开关

演示账号写在选择页和 HANDOFF：老板 `owner@demo.shop` / `demo`；顾客 `jane@demo.shop` / `demo`。

## 6. 必须能点通的故事（人类验收就点这些）

用 mock 预填：一家卖家居物件的店（不是服装模板，但商品带「颜色」「尺寸」选项）。国内一份中文货，出海一份英文货，各 6–10 件，图要统一气质。

1. **空白气质**：能切到「空 Catalog」看空店，再切回演示货。空店仍有店名、页脚、说明页空文案。
2. **逛和买**：首页 → 商品 → 选一款有库存的 → 车 → 被要求登录 → 结账选运费 → 可填一个优惠码 → 国内走支付宝假成功 / 出海走 PayPal 或 Stripe 假成功 → 看到下单成功信预览。
3. **卖光**：某一款库存 0，详情页不能加入购物车。
4. **老板发货**：后台看到新订单 → 填运单号 → 顾客订单页看到单号 → 已发货信预览。
5. **退**：顾客申请 → 老板收件箱或订单里同意/拒绝 → 未发货同意后状态变已退；已发货同意后出现「请寄回」而不是立刻退款。
6. **客服**：未登录问运费，AI 用运费说明页答；登录后问「我的订单」，能对上这一单；说「我要退款」转人工，后台收件箱出现线程。
7. **店铺资料**：改店名和标志，页眉、结账顶、邮件预览一起变。国内填 ICP，页脚出现可点击链接。
8. **微信灰**：国内收款设置与结账，微信可见不可用。
9. **语言货币（出海）**：切语言，按钮变、没译的商品名仍主语言；切货币，价格按手填汇率变。
10. **桌面 + 手机宽度**都要能走完购买。

## 7. 分阶段交付（按顺序，每阶段可演示）

**阶段 A：壳**  
选站页、店面布局（顶栏、页脚、聊天按钮）、后台壳（左栏）、色板与字体、空态。

**阶段 B：店面买卖**  
商品列表/详情/车/登录/结账/假支付/订单页。库存 0。优惠码一枚可用。

**阶段 C：后台经营**  
上架（含自定义选项名）、改库存与现价/原价、分类、发货填单号、优惠码 CRUD、四篇说明编辑、店铺资料、收款（含灰微信）、运费、SMTP 表单、语言货币。

**阶段 D：售后与客服**  
退货申请双方状态机；聊天 + 假 AI（规则：命中说明页关键词；命中订单；命中退款则转人工）。不要接真模型。

**阶段 E：打磨与验收**  
空店切换、中英软件字、响应式、无障碍焦点、HANDOFF.md、自检第 8 节。

不要一上来做动画秀。运动服务于层次和反馈。`prefers-reduced-motion` 要尊重。

## 10. 人类怎么验收

人类只点浏览器，不读你的实现细节。请准备一条「5 分钟演示路径」写在 HANDOFF 最上面：选出海站 → 买一件 → 登录 → 付 → 切后台发货 → 再以顾客看单号 → 打开聊天说退款看到转人工。

国内站再走一遍支付宝与灰色微信、ICP 页脚。
