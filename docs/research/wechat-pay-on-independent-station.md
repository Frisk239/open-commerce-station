# 国内独立站接微信收款，难在哪

讨论用。不是现在就要接上。

## 难，是真的

独立站是自己的网站（电脑 + 手机浏览器），不是小程序。微信收款在这种站上，官方其实是**好几套**：

| 顾客怎么打开店 | 微信要的那一套 |
| --- | --- |
| 电脑上，出示二维码用微信扫 | Native（扫码） |
| 手机上，用 Safari / 系统浏览器 | H5（要报域名，审核要等几天） |
| 手机上，从微信里点开链接 | 另一套（还要认证过的服务号，还要拿到这个人的微信身份） |

漏一套，就有人付不了。支付宝电脑网站支付，一套就能覆盖「打开网页付款」；你们沙箱已经跑通过。微信不是这个手感。

另外几件磕磕绊绊的事：

- 商户号之外，H5 还常要网站主体一致、经营性备案一类材料。
- 支付域名要报备，和页面地址对不上就报「商家参数未配置」。
- 本地电脑、没有备案的测试域名，H5 经常调不起来；必须用真站点跳转，不能随便把支付链接粘到地址栏。
- 沙箱/仿真不是支付宝那种「开箱就能付 0.01 元」的体验，很多人最后只能拿真实商户号小额测。

所以：第一版国内只做支付宝，不是偷懒，是独立站接微信的开发调试成本确实高。

## 以后怎么补比较稳

产品里先留「还能再开一种收款」的位置。真做微信时，**先做电脑扫码那一套**（最接近现在的独立站结账），手机浏览器和微信内打开再分开做。不要三套一起上。
